# ESP32-S3 Migration Plan

## Overview

Migrate from ESP32-WROOM to ESP32-S3. The S3 has a different RMT peripheral architecture with implications for LED driving, plus different clock sources and memory layout.

## Key Differences: ESP32 vs ESP32-S3

### RMT Peripheral

| Feature | ESP32 | ESP32-S3 |
|---------|-------|----------|
| RMT channels | 8 (shared TX/RX) | 4 TX + 4 RX (dedicated) |
| Memory per channel | 64 symbols (shared 512 total) | 48 symbols per channel |
| DMA support | No | Yes |
| Clock sources | APB (80 MHz) | APB (80 MHz), XTAL (40 MHz), RC_FAST (~17.5 MHz) |
| Max resolution | 80 MHz | 80 MHz |

### Memory Architecture

| Feature | ESP32 | ESP32-S3 |
|---------|-------|----------|
| Internal RAM | 520 KB | 512 KB |
| PSRAM support | Up to 4 MB (QSPI) | Up to 8 MB (Octal SPI) |
| DMA-capable memory | DRAM only | DRAM + PSRAM (with cache) |

### CPU & Clocking

| Feature | ESP32 | ESP32-S3 |
|---------|-------|----------|
| CPU cores | 2x Xtensa LX6 @ 240 MHz | 2x Xtensa LX7 @ 240 MHz |
| Default APB clock | 80 MHz | 80 MHz |
| XTAL | 40 MHz typical | 40 MHz typical |

### GPIO

| Feature | ESP32 | ESP32-S3 |
|---------|-------|----------|
| GPIO count | 34 | 45 |
| RMT-capable GPIOs | Most GPIOs | Most GPIOs |
| Strapping pins | GPIO0, 2, 5, 12, 15 | GPIO0, 3, 45, 46 |

## Current Implementation Analysis

**File**: `components/led/ws2811.c`

```c
#define WS2811_RESOLUTION_HZ 10000000  // 10MHz resolution

rmt_tx_channel_config_t tx_chan_config = {
    .clk_src = RMT_CLK_SRC_DEFAULT,
    .gpio_num = gpioNum[i],
    .mem_block_symbols = 64,           // ESP32-specific
    .resolution_hz = WS2811_RESOLUTION_HZ,
    .trans_queue_depth = 4,
    .flags.with_dma = false,           // Could enable on S3
};
```

### Timing Analysis

Current timing at 10 MHz (100ns per tick):

| Symbol | Ticks | Actual Time | WS2811 Spec |
|--------|-------|-------------|-------------|
| T0H | 3 | 300ns | 350ns ±150ns |
| T0L | 8 | 800ns | 800ns ±150ns |
| T1H | 7 | 700ns | 700ns ±150ns |
| T1L | 4 | 400ns | 600ns ±150ns |

The timing is within spec and should work identically on S3 since both use the same 10 MHz resolution derived from APB clock.

## Migration Steps

### Step 1: Update sdkconfig.defaults

Add S3-specific target configuration:

```ini
# Target selection (uncomment one)
# CONFIG_IDF_TARGET_ESP32=y
CONFIG_IDF_TARGET_ESP32S3=y

# ESP32-S3 specific settings
CONFIG_ESP32S3_DEFAULT_CPU_FREQ_240=y
CONFIG_ESP32S3_DEFAULT_CPU_FREQ_MHZ=240

# Flash configuration for S3
CONFIG_ESPTOOLPY_FLASHMODE_QIO=y      # S3 supports QIO
CONFIG_ESPTOOLPY_FLASHFREQ_80M=y      # S3 can run 80 MHz flash
CONFIG_ESPTOOLPY_FLASHSIZE_4MB=y

# Optional: Enable PSRAM if your module has it
# CONFIG_ESP32S3_SPIRAM_SUPPORT=y
# CONFIG_SPIRAM_MODE_OCT=y
```

### Step 2: Update Kconfig.projbuild GPIO Ranges

ESP32-S3 has more GPIOs (0-48):

```diff
 config LED_GPIO_A
     int "LED channel A GPIO number"
-    range 0 39
+    range 0 48
-    default 26
+    default 38
     help
         GPIO number (IOxx) attached to the first LED control wire.

 config LED_GPIO_B
     int "LED channel B GPIO number"
-    range 0 39
+    range 0 48
-    default 27
+    default 39
     help
         GPIO number (IOxx) attached to the second LED control wire.
```

**Note**: GPIO 26-32 don't exist on ESP32-S3. Choose new defaults (e.g., 38, 39).

### Step 3: Update RMT Configuration for S3

**File**: `components/led/ws2811.c`

#### Option A: Conservative (no DMA)

Minimal changes - just adjust memory block size:

```diff
 rmt_tx_channel_config_t tx_chan_config = {
     .clk_src = RMT_CLK_SRC_DEFAULT,
     .gpio_num = gpioNum[i],
-    .mem_block_symbols = 64,
+    .mem_block_symbols = 48,    // S3 has 48 symbols per channel
     .resolution_hz = WS2811_RESOLUTION_HZ,
     .trans_queue_depth = 4,
     .flags.with_dma = false,
 };
```

#### Option B: Enable DMA (recommended for long LED strips)

DMA allows larger transfers without blocking:

```diff
 rmt_tx_channel_config_t tx_chan_config = {
     .clk_src = RMT_CLK_SRC_DEFAULT,
     .gpio_num = gpioNum[i],
-    .mem_block_symbols = 64,
+    .mem_block_symbols = 64,    // Can be larger with DMA
     .resolution_hz = WS2811_RESOLUTION_HZ,
     .trans_queue_depth = 4,
-    .flags.with_dma = false,
+    .flags.with_dma = true,     // Enable DMA on S3
 };
```

**DMA Benefits**:
- CPU doesn't need to feed RMT memory during transmission
- Lower latency for long LED strips
- More consistent timing

**DMA Requirements**:
- Buffer must be in DMA-capable memory (internal SRAM, not PSRAM without cache)
- May need `MALLOC_CAP_DMA` for buffer allocation

### Step 4: Target-Specific Configuration

Use ESP-IDF's built-in `CONFIG_IDF_TARGET_*` defines for conditional compilation:

**File**: `components/led/ws2811.c`

```c
#include "sdkconfig.h"

#if CONFIG_IDF_TARGET_ESP32S3
    #define RMT_MEM_BLOCK_SYMBOLS 48
    #define RMT_USE_DMA true
#elif CONFIG_IDF_TARGET_ESP32
    #define RMT_MEM_BLOCK_SYMBOLS 64
    #define RMT_USE_DMA false
#else
    #error "Unsupported target - requires ESP32 or ESP32-S3"
#endif

// In ws2811_init():
rmt_tx_channel_config_t tx_chan_config = {
    .clk_src = RMT_CLK_SRC_DEFAULT,
    .gpio_num = gpioNum[i],
    .mem_block_symbols = RMT_MEM_BLOCK_SYMBOLS,
    .resolution_hz = WS2811_RESOLUTION_HZ,
    .trans_queue_depth = 4,
    .flags.with_dma = RMT_USE_DMA,
};
```

**File**: `main/Kconfig.projbuild`

Update GPIO config to be target-aware:

```
config LED_GPIO_A
    int "LED channel A GPIO number"
    range 0 48 if IDF_TARGET_ESP32S3
    range 0 39 if IDF_TARGET_ESP32
    default 38 if IDF_TARGET_ESP32S3
    default 26 if IDF_TARGET_ESP32
    help
        GPIO number (IOxx) attached to the first LED control wire.

config LED_GPIO_B
    int "LED channel B GPIO number"
    range 0 48 if IDF_TARGET_ESP32S3
    range 0 39 if IDF_TARGET_ESP32
    default 39 if IDF_TARGET_ESP32S3
    default 27 if IDF_TARGET_ESP32
    help
        GPIO number (IOxx) attached to the second LED control wire.
```

This allows:
- Different default GPIOs per target
- Correct GPIO range validation per target
- Single codebase for both chips

### Step 5: DMA-Safe Buffer Allocation

Update `ws2811_setColors()` to conditionally allocate DMA-capable memory on S3:

**File**: `components/led/ws2811.c`

Add include:
```c
#include "esp_heap_caps.h"
```

Update allocation:
```c
#if CONFIG_IDF_TARGET_ESP32S3
        channel_buffers[chan] = heap_caps_malloc(buffer_size, MALLOC_CAP_DMA);
#else
        channel_buffers[chan] = malloc(buffer_size);
#endif
```

Or use a helper macro at the top of the file:
```c
#if CONFIG_IDF_TARGET_ESP32S3
    #define WS2811_ALLOC(size) heap_caps_malloc(size, MALLOC_CAP_DMA)
#else
    #define WS2811_ALLOC(size) malloc(size)
#endif

// Then in ws2811_setColors():
channel_buffers[chan] = WS2811_ALLOC(buffer_size);
```

### Step 6: Update CMakeLists.txt (if needed)

No changes should be required - ESP-IDF handles target-specific builds.

### Step 7: Clean Build

```bash
# Set target to ESP32-S3
idf.py set-target esp32s3

# Clean and rebuild
idf.py fullclean
idf.py build
```

## Clock Source Considerations

### RMT Clock Sources on S3

| Source | Frequency | Notes |
|--------|-----------|-------|
| `RMT_CLK_SRC_DEFAULT` | 80 MHz (APB) | Same as ESP32, recommended |
| `RMT_CLK_SRC_APB` | 80 MHz | Explicit APB selection |
| `RMT_CLK_SRC_XTAL` | 40 MHz | More stable, lower power |
| `RMT_CLK_SRC_RC_FAST` | ~17.5 MHz | Low power, less accurate |

**Recommendation**: Keep `RMT_CLK_SRC_DEFAULT` (APB @ 80 MHz). The 10 MHz resolution divides evenly from both 80 MHz APB and 40 MHz XTAL.

### Timing Verification

The WS2811 timing should be identical because:
1. Same APB clock (80 MHz) on both chips
2. Same resolution (10 MHz) configured
3. Same tick duration (100ns)

However, verify with oscilloscope after migration:
- T0H: 300-350ns
- T0L: 800-850ns
- T1H: 700-750ns
- T1L: 400-450ns
- Reset: >50μs

## Hardware Considerations

### Recommended ESP32-S3 Modules

| Module | Flash | PSRAM | Notes |
|--------|-------|-------|-------|
| ESP32-S3-WROOM-1 | 4-16 MB | None | Direct replacement |
| ESP32-S3-WROOM-1U | 4-16 MB | None | U.FL antenna |
| ESP32-S3-WROOM-2 | 16-32 MB | 8 MB Octal | For large buffers |

### GPIO Mapping

| Function | ESP32 GPIO | ESP32-S3 GPIO | Notes |
|----------|------------|---------------|-------|
| LED Channel A | 26 | 38 | Pick any non-strapping GPIO |
| LED Channel B | 27 | 39 | Pick any non-strapping GPIO |
| USB D- | N/A | 19 | Built-in USB-JTAG |
| USB D+ | N/A | 20 | Built-in USB-JTAG |

**Avoid on S3**: GPIO 0, 3, 45, 46 (strapping pins)

### Power Considerations

- ESP32-S3 typical current: ~100-150mA (WiFi active)
- Similar to ESP32-WROOM
- Ensure 3.3V supply can handle peak current

## Rollback Plan

Keep the ESP32-WROOM code working by using conditional compilation. To switch back:

```bash
idf.py set-target esp32
idf.py fullclean
idf.py build
```

## Future Improvements with S3

1. **USB-JTAG debugging**: Built-in USB for programming and debugging
2. **Larger frame buffers**: With PSRAM, could increase `CONFIG_LED_FRAME_BUFFER_SIZE`
3. **Vector instructions**: S3's LX7 has SIMD - potential for faster pixel processing
4. **More RMT channels**: Could support up to 4 independent LED strips
